# قرار معماري ADR-001: خدمة محلية + عملاء سطح مكتب

- **التاريخ:** 2026-10-23
- **الحالة:** معتمد (بموافقة صاحب النظام على القرارات العشرة)
- **النطاق:** النسخة الأولى من نظام السجل الوظيفي والعلاوات والترفيعات

## 1. السياق

المتطلبات الملزمة التي تحكم القرار:

1. العمل **دون إنترنت بالكامل** في المركز والمؤسسات، وتبادل البيانات عبر **USB** فقط.
2. **أقل من 5 مستخدمين متزامنين** في المؤسسة، وأقل من 5 في المركز.
3. مؤسسة واحدة قد تحوي **2000 موظف** موزعين على 4 مستخدمين (كل مستخدم على حصته).
4. تسجيل الدخول إلزامي، والصلاحيات تُفحص في طبقة الخدمة لا في الواجهة فقط.
5. المواصفة (§3.9، §5.1) تقترح PostgreSQL + خدمة ASP.NET Core، لكنها تسمح بتعديل الاختيار التقني قبل التعاقد **بشرط توثيق قرار معماري يحقق المتطلبات نفسها**.
6. المواصفة تمنع صراحة مشاركة ملف SQLite عبر مجلد شبكة (§16).

## 2. القرار

**خدمة محلية واحدة لكل جهة (مركز أو مؤسسة) + عملاء سطح مكتب.**

```text
عميل 1 ─┐
عميل 2 ─┼── شبكة داخلية ──► خدمة محلية (SQLite/WAL) ──► بيانات + تدقيق + نسخ
عميل 3 ─┘                        │
                                 └── USB: حزم بيانات/قواعد/نتائج
```

- **نفس الملف التنفيذي بثلاثة أوضاع:** عميل (افتراضي)، `--server`، `--standalone`
  (خدمة + واجهة في عملية واحدة للمستخدم الواحد).
- **كل المنطق في الخدمة:** المصادقة، الصلاحيات، التحقق، المعاملات، التدقيق، الاحتساب،
  الحزم، النسخ الاحتياطي. العميل يعرض وينادي فقط.
- **قاعدة البيانات:** SQLite بوضع WAL، اتصال لكل خيط، قفل كتابة واحد، `busy_timeout`.
- **الحزم:** حاوية واحدة `.amdhpkg` (بيان + بصمة SHA-256 + توقيع HMAC لاحقاً) بثلاثة
  أنواع محتوى: بيانات (مؤسسة ← مركز)، قواعد (مركز ← مؤسسة)، نتائج (مركز ← مؤسسة).
- **ملكية البيانات:** المركز لا يعدّل بيانات موظفي المؤسسات؛ يعتمد حالتها فقط. أي تصحيح
  يعود للمؤسسة عبر «طلب تصحيح» في حزمة النتائج. هذا يُلغي الحاجة إلى محرك تعارض معقد.

## 3. الأدوار والنطاق

| الدور | الرمز | النطاق |
|---|---|---|
| مدير المركز | `center_admin` | كل المؤسسات + المركز؛ الاعتماد النهائي وإدارة القواعد والمستخدمين |
| مدخل المركز | `center_editor` | موظفو المركز المخصصون له |
| مدير المؤسسة | `unit_manager` | كل موظفي مؤسسته؛ التدقيق والاعتماد المحلي والتوزيع |
| مدخل المؤسسة | `unit_editor` | الموظفون المخصصون له فقط |

التخصيص (`user_employee_assignments`) للرؤية والتحرير فقط، وليس تقسيم بيانات: قاعدة
المؤسسة واحدة، والتصدير للمركز حزمة واحدة للمؤسسة.

## 4. البدائل المرفوضة

| البديل | سبب الرفض |
|---|---|
| ملف SQLite على مجلد مشترك | تلف محتمل عند تعدد الكُتّاب، ومخالف §16 |
| قاعدة مستقلة لكل مستخدم ثم دمج | يكسر الكتب الجماعية ونقل الموظف بين الحصص، ويضاعف التعارضات |
| PostgreSQL في كل مؤسسة | تثبيت وصيانة ثقيلة على مركز صحي، بلا حاجة لحجم البيانات |
| واجهة ويب محلية | تُلغي الاستفادة من واجهة سطح المكتب الحالية، وتُضاعف إعادة البناء |

## 5. النتائج والالتزامات

- **إيجابيات:** تزامن آمن، فحص صلاحيات مركزي، سجل تدقيق واحد، نسخ احتياطي واحد،
  واستمرار العمل بلا إنترنت.
- **سلبيات:** الجهاز الذي يشغّل الخدمة نقطة فشل واحدة → تشغيل تلقائي مع Windows،
  نسخة احتياطية يومية، واستعادة موثقة على جهاز آخر.
- **قابلية الترحيل:** يُمنع SQL خاص بـSQLite في طبقة الخدمات، وتُستخدم UUID وتواريخ
  موحدة، حتى يمكن استبدال الطبقة لاحقاً بـPostgreSQL دون إعادة كتابة الواجهة.
- **الأمان:** ربط الخدمة بالشبكة الداخلية فقط، جلسات موقعة، تجزئة كلمات المرور، قفل
  بعد المحاولات. TLS بشهادة ذاتية يُضاف في مرحلة التقوية.

## 6. ما لا يغطيه هذا القرار (مؤجل)

- التوقيع الرقمي PKI (يُستبدل الآن ببصمة SHA-256 + كلمة مرور حزمة).
- MFA، وسياسة تدوير مفاتيح.
- الترحيل إلى PostgreSQL إذا تجاوز المركز حد التزامن المتفق عليه.
